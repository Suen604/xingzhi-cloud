# 功能实现与配置

## 当前实现

- 后端统一版本标记；许可证参数只为命令行兼容保留。静态资源接受同版本的社区版和 Pro 包。
- QQ OAuth、Logto OIDC 登录与已登录账户绑定。Logto 校验签名、签发者、受众、有效期和 nonce，并使用 PKCE。第三方邮箱不会自动绑定已有账户；账户原有两步验证仍会执行。
- 支付宝 RSA2 网页支付、微信支付 API v3 Native 支付。支付通知校验签名、商户、订单金额和币种；订单发放与权益更新在同一事务中执行，重复通知不重复发放。
- 商品销售永久容量或永久用户组权益；商品总价由服务端读取，不接受客户端报价。用户组商品不能授予管理员组。尚未实现退款、期限会员、用户余额或自动分账。
- 兑换码批量生成、有效期、单次兑换。数据库仅保存兑换码哈希，完整码仅在生成时返回。
- 操作审计的分页查询与过滤；只记录操作者、路由、资源路径、HTTP 状态和 IP，不存储请求正文、查询参数或令牌。当前为操作级审计，不等同于上游每种业务事件的完整活动流。
- 登录用户举报分享；管理员可忽略举报或禁用分享。订单、审计、举报入口已连接实际接口。
- 随机负载均衡存储策略：每次上传选择一个实际策略，实体保存该策略用于后续读取。禁止嵌套负载均衡；依赖中的子策略不能删除。
- 用户组可分配额外存储策略；用户可在 `/shop` 选择新上传使用的策略。现有实体位置不会因此改变。
- 用户引用类型的自定义属性、用户组默认固定入口、额外邮件模板编辑器。
- 文件和文件夹的协作授权：只读/可编辑成员、文件夹权限继承、调整及撤销权限、“与我共享”列表；协作上传按所有者的存储策略和容量记账。
- 文件和文件夹收费分享：设置人民币解锁价，买家登录后通过支付宝或微信支付购买；支付到账后解锁，分享者可在“我的分享”查看销售订单。

## 收费分享

先在管理面板配置支付宝或微信支付商户参数，然后在创建或编辑分享时启用“收费分享”。价格范围为 **0.01–1,000,000.00 元**，最多两位小数；数据库与订单以整数分保存。关闭收费选项会将价格设为零。旧客户端更新分享时未提交 `price` 字段，会保留原价。

买家打开分享，先通过密码检查（如有），再登录并付款。支付宝使用网页收银台，微信使用 Native 支付二维码。界面只在服务端收到验签通过的通知并完成订单事务后解锁；浏览器跳转、订单号或客户端提交的金额均不能作为付款凭据。

一次购买绑定**买家账户、分享、源文件/目录及分享者**，在分享有效期间有效。调价不会使已付款用户重复购买；更换分享的源文件不能套用旧订单。购买不延长分享有效期、不重置下载次数、不绕过密码或用户组访问权限，也不会授予所有者文件系统的协作权限。目录内后续新增内容按该目录分享访问，购买不冻结内容版本。

所有款项进入**站点配置的支付商户**。“我的分享 → 收费分享销售订单”展示本人分享的订单、支付状态与已收款合计；它不是可提现余额。当前没有自动分账、提现或自动退款。分享删除、过期或源文件更换后收到的合法付款仍会记为已收款，需由站点管理员按订单人工处理售后。

订单使用服务端生成的价格与资源快照，有效等待时间为 30 分钟；重复打开相同渠道、相同报价的未过期订单会复用该订单。已验证的延迟支付通知仍会入账，重复回调不会重复发放权益。未付款不能列目录、预览或申请下载地址；恢复的导航缓存和文件事件连接同样重新检查付款状态。已发放的临时下载地址、已下载副本遵循原有有效期，收费设置无法回收这些数据。

相关接口：

- `POST /api/v4/commerce/share-orders`：登录买家提交 `share_id`、`password`（如需）和 `provider`（`alipay` 或 `wechat`），服务端读取价格。
- `GET /api/v4/commerce/orders/:number`：仅买家可查询该订单，用于支付结果轮询。
- `GET /api/v4/commerce/share-sales`：仅查询当前账户作为分享者的销售记录，支持 `page` 和 `page_size`。

原有分享接口增加 `price`（整数分）设置与响应字段；分享详情增加 `purchased`。启动时增量增加分享价格及订单资源快照字段，不清除既有数据。

## 文件权限与协作

所有者在文件详情或创建分享对话框中点击“权限与协作”，搜索已注册用户后添加成员。接收方从导航栏“与我共享”进入文件夹，也可直接打开获授权的文件地址。协作授权独立于公开分享链接，无需创建公开链接。

| 操作 | 只读成员 | 可编辑成员 | 所有者 |
| --- | --- | --- | --- |
| 浏览、预览、下载、复制到有写入权限的目录 | 是 | 是 | 是 |
| 新建、上传、修改内容与元数据、重命名 | 否 | 是 | 是 |
| 同一所有者下移动、移入回收站、管理文件版本 | 否 | 是 | 是 |
| 永久删除文件、恢复回收站、创建公开分享、管理成员 | 否 | 否 | 是 |

文件夹授权由所有子项继承；多个直接或继承授权取最高权限，不存在拒绝规则。成员列表标明继承来源，继承授权需回到来源目录调整。删除某个直接授权不会移除另一个目录授予的权限。移动文件不会转移所有权；跨所有者移动被拒绝，可通过复制保存副本，复制不会复制原文件的成员授权。删除整棵文件树后，原有协作授权不能访问回收站中的内容。

每次跨所有者访问、写入和上传完成都会查询当前数据库授权；导航缓存不会保留已撤销的权限。文件事件连接在发送事件和心跳前重新检查授权。已发放的存储服务上传凭证、临时下载地址及已下载的副本遵循原有有效期和存储服务行为；撤销协作权限不会远程回收这些副本或让既有签名地址立即失效。降权后的在途上传不能完成入库。

并发写入继续使用文件锁与原有版本校验，在线 Office 编辑器会根据成员权限报告只读/可写状态；编辑器本身需按项目原有方式配置。这不是字符级实时合并编辑器。

权限接口为 `GET /api/v4/file/permissions?uri=...`、`PUT /api/v4/file/permissions` 和 `DELETE /api/v4/file/permissions`，均需登录且仅允许文件所有者操作。写入 JSON 包含 `uri`、`user_id`（用户 hash ID），添加/更新时还需 `role`（`viewer` 或 `editor`）。数据库启动迁移会增量创建 `file_permissions` 表。

## 配置入口

管理面板“用户与会话”的第三方登录区配置 QQ 和 Logto；“增值服务”区配置支付宝、微信支付、商品和兑换码。“事件”区配置审计开关并查看日志。用户从“商店与存储”进入购买、兑换、绑定账户和存储选择。

第三方登录回调地址（`https://example.com` 应替换为站点配置中的公网地址）：

| 平台 | 回调 |
| --- | --- |
| QQ | `https://example.com/api/v4/sso/qq/callback` |
| Logto | `https://example.com/api/v4/sso/logto/callback` |

QQ 需要 App ID 和 App Key；Logto 需要传统 Web 应用的 Client ID、Client secret 和 OIDC issuer。注册同时遵循全站注册开关与该提供方的注册开关。已有账户应先登录，再从商店页面绑定。

支付宝需要 App ID、卖家 ID、商户 RSA 私钥和支付宝公钥（PEM），可选择沙箱。微信需要 App ID、商户号、商户私钥、商户证书序列号、API v3 密钥，以及平台公钥/证书与对应 ID/序列号。更换微信平台公钥时，需同步更新 ID。

| 平台 | 支付通知 |
| --- | --- |
| 支付宝 | `https://example.com/api/v4/payments/alipay/notify` |
| 微信 | `https://example.com/api/v4/payments/wechat/notify` |

这些参数存入 `extensions_config`；通用设置读取会屏蔽该项，专用管理接口会掩码私密字段。不要把实际密钥加入源码或前端资源。

## 前端源码与构建

前端仍为上游子模块。修改以主仓库补丁保存，避免引用未发布的子模块提交。

```bash
git submodule update --init assets
bash .build/apply-assets-patch.sh
bash .build/build-assets.sh 4.14.0
go build -o cloudreve .
```

补丁会校验是否已经应用。对子模块切换提交或有冲突时，脚本会明确失败，避免静默构建旧界面。

首次启动会以 Ent 的增量 schema 更新创建新表并为用户增加 `extra_storage` 列；不会清除既有文件与用户数据。

## 尚未完成

本次实现不等同于完整上游 Pro 产品。文件协作目前提供用户级只读/编辑授权，尚无用户组授权、逐操作自定义权限、拒绝规则或字符级实时合并。其他仍缺少自动分账与提现、存储策略迁移、目录直链、下载节点权限与选择、全站初始分享快捷方式、注册邮箱规则、公告及应用反馈配置、用户积分与期限会员，以及配额通知/收据邮件的完整触发流程。未实现功能的入口保留并明确标为“尚未实现”，不再提示购买许可证。

第三方平台的线上连通、应用审核和真实交易需在配置应用与商户参数后验证；本地测试使用生成的密钥、模拟 OIDC 提供方和 SQLite，不会产生真实扣款。
